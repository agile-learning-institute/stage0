# Exercise Skill: Structuring Design Workshops with Observe/Reflect/Make

## Overview
This skill defines how to structure design workshops and exercises using the Observe/Reflect/Make framework. Each exercise is conducted as a Discord post (or forum thread) where participants progress through three distinct phases of interaction, all structured around channel-based communication.

## Core Concept: Three-Part Exercise Structure
Every design exercise follows this exact sequence:
1. **Observe** - Individual observation gathering
2. **Reflect** - Group synthesis and pattern recognition  
3. **Make** - Decision making and action assignment

## Channel and Post Usage
- **Each exercise = One Discord post** (in a designated exercises channel/forum)
- **Participants respond** to the exercise post with their contributions for each phase
- **Phase transitions** are signaled by reactions or explicit facilitator calls
- **Exercise documentation** evolves within the same post as participants contribute

## Phase Details

### 1. OBSERVE Phase
**Purpose**: Gather individual observations without discussion or influence.

**Channel Usage**:
- Participants post observations as replies to the exercise post
- No discussion, cross-talk, or reactions during Observe (except phase completion signal)
- Observations should be brief (think: 3"x3" sticky note size)
- Focus on quantity over quality - more ideas are better than fewer perfect ones

**Common Observe Patterns**:
- List format (one item per reply or comma-separated)
- Categorical observation (does/says/thinks/feels)
- Structured format ("<who> does <what> and then <wow>")
- Ranking lists (impact, feasibility)
- Free-form observations grouped by category

**Completion Signal**: 
- Participants react with 👍 when they have completed their observations
- Facilitator calls transition when sufficient observations gathered

### 2. REFLECT Phase
**Purpose**: Synthesize individual observations into shared understanding.

**Channel Usage**:
- Participants collaboratively edit/transform the exercise post
- Replace placeholder text with synthesized observations
- Use formatting to indicate patterns, consensus, or groupings
- Build upon previous contributions to create coherent summary

**Common Reflect Patterns**:
- Transform raw observations into bulleted lists
- Apply formatting based on consensus levels (*italics* for 2 people, **bold** for 3, ***bold italics*** for all)
- Group observations into categories using markdown headings
- Identify patterns, themes, causal threads
- Create structured outlines (level 1 headers for main categories, l2/l3 for themes)
- Bold verbatim duplicates to show common observations
- Calculate averages or aggregate data (rankings, frequencies)

**Completion Signal**: 
- When the synthesized reflection is complete and understood by all
- Facilitator verifies shared understanding before proceeding

### 3. MAKE Phase
**Purpose**: Convert understanding into decisions, actions, and plans.

**Channel Usage**:
- Participants propose and agree on concrete outcomes
- Create actionable items: decisions, assignments, schedules, plans
- Document commitments within the exercise post
- Often involves scheduling follow-up exercises or making assignments

**Common Make Patterns**:
- Create lists of unique ideas/decisions with names
- Build roadmaps (now/next/later) or timelines
- Assign action items to specific people
- Schedule follow-up exercises (empathy mapping, prioritization, etc.)
- Identify key focus areas for next exercises
- Make consensus decisions about direction

**Completion Signal**: 
- When concrete outcomes are documented and agreed upon
- Clear next steps are established

## Exercise Skill Definition
This skill defines the structure that can be applied to any design exercise. An exercise using this skill must include:

### Required Components:
1. **Clear Purpose Statement** - What the exercise aims to accomplish
2. **Observe Instructions** - How to gather individual observations
3. **Reflect Instructions** - How to synthesize observations into shared understanding  
4. **Make Instructions** - How to convert understanding into decisions/actions
5. **Completion Signals** - Clear indicators for when each phase is complete

### Channel Management:
- Designate specific channel/forum for exercises
- Each exercise gets its own post (thread if using forum format)
- Maintain exercise post as living document through all three phases
- Use reactions for phase completion signals (👍 for Observe completion)
- Facilitator guides transitions between phases

### Participant Flow:
1. Read exercise purpose and Observe instructions
2. Contribute observations as replies to exercise post (Observe phase)
3. React with 👍 when observations complete
4. Wait for Reflect phase signal
5. Collaboratively transform exercise post to synthesize observations (Reflect phase)
6. Wait for Make phase signal  
7. Propose and agree on concrete outcomes/actions (Make phase)
8. Document decisions/actions in exercise post
9. Exercise complete

## Benefits of This Structure
- **Consistency**: All exercises follow familiar pattern, reducing cognitive load
- **Clarity**: Clear phases prevent mixing observation with judgment
- **Inclusivity**: Individual Observe phase ensures all voices heard before group discussion
- **Efficiency**: Structured reflection accelerates shared understanding
- **Action-Oriented**: Make phase ensures exercises lead to concrete outcomes
- **Scalable**: Structure works for simple (colors) to complex (stakeholder mapping) exercises
- **Extensible**: New exercises can be added by filling in the three-phase template

## Creating New Exercises
To create a new exercise using this skill:
1. Define the exercise purpose (what insight/outcome is needed)
2. Write Observe instructions (how to gather raw data/observations)
3. Write Reflect instructions (how to synthesize observations into understanding)
4. Write Make instructions (how to convert understanding to actions/decisions)
5. Add to exercises channel as new post
6. Guide participants through the three phases

## Example Application
Looking at existing exercises in ChatDesignThinking.md:
- **Stakeholders**: Observe (list stakeholders) → Reflect (group into Users/Partners/Vendors) → Make (identify for empathy maps, assign Rolodex tasks)
- **Empathy Map**: Observe (do/say/think/feel observations) → Reflect (synthesize under headers with themes) → Make (identify pain points for big ideas exercise)
- **Priority**: Observe (rank impact & feasibility) → Reflect (categorize into no-brainers/big bets/utilities/unwise) → Make (create now/next/later roadmap)

This structure can be applied to any design thinking exercise, workshop activity, or collaborative sensemaking session.

## Implementation Notes
- Facilitator responsible for guiding phase transitions
- Time-boxing may be applied to each phase as needed
- Exercises can be run synchronously (real-time) or asynchronously (participants contribute when able)
- The skill is technology-agnostic but implemented here using Discord posts/reactions
- Future implementations could adapt this structure to other collaboration platforms
